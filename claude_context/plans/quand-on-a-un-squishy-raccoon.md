# Conversion G-code 3 axes → polaire Apex (script Python) + bouton Export

## Contexte
La Prévisualisation lit déjà les G-codes cartésiens (Anycubic, Creality, IceSL…) mais l'Apex imprime en
polaire (`G00 Y<C> X<R> Z<Z> B<B> E<e> F<f>`, cf. doc en tête de `src/components/gcodeLayer.ts`). Il faut :
1. une **carte « Conversion »** avec message d'avertissement, sous le panneau du bas de Prévisualisation
   (zone du rectangle bleu, au-dessus de la barre d'aide), visible quand le G-code chargé est 3 axes ;
2. un **script Python** qui convertit chaque ligne en polaire, et en mode **angle dynamique** calcule
   l'inclinaison optimale de la tête (B, ±45°) pour les G-codes non plans, en tenant compte des 46 mm
   pointe de buse ↔ pivot (`NOZZLE_PIVOT_MM`) ;
3. le résultat converti chargé dans la Prévisualisation (plateau qui tourne, tête qui s'incline) ;
4. le **bouton Slice devient « Export »** dans l'espace Prévisualisation, et enregistre le G-code polaire.

L'UI sera livrée en EXE Electron (`electron/main.cjs`, aujourd'hui sans preload ni IPC) : Python y est
**embarqué** (distribution « embeddable » officielle Windows, stdlib seule), lancé par le process main.

## 1. Script Python — `python/gcode_to_polar.py` (nouveau, stdlib uniquement)
CLI : `gcode_to_polar.py <in> <out> --mode polar|dynamic --center-x --center-y --pivot 46 --b-limit 45 --tol 0.01`
(le centre plateau est passé par l'UI : même règle que le parseur TS — `printable_area`/`bed_shape`,
`bed_size_*`, sinon centre de la pièce — une seule source de vérité).
- **État modal** comme `parseGCode` : G90/G91, M82/M83, G92, G20/G21, arcs G2/G3 (I/J ou R) linéarisés.
- **Sortie** : `M82` en tête, E converti en **absolu** (format Apex) ; chaque mouvement → une ou plusieurs
  lignes `G00 Y<C> X<R> Z<Z> B<B> [E<e>] F<f>` (5 décimales). Commentaires et commandes non-mouvement
  (`;TYPE:`, `;WIPE_*`, M-codes, SET_VELOCITY_LIMIT…) **recopiés tels quels** → légende, stats et
  détection de slicer restent valables sur le fichier converti. En-tête ajouté :
  `; generated by Apex G-code converter 1.0 (source: …, mode: …)`.
- **Polaire** : `r = hypot(x−cx, y−cy)`, `C = atan2(y−cy, x−cx)` en degrés, **déroulé** (jamais modulo
  360 : `C = C_prev + wrap(θ − C_prev)`), C conservé quand r < 1e-3 (singularité du centre ; un segment
  qui traverse le centre est coupé au centre, le plateau pivote sur place). Même convention que le rendu
  (`createSampler` / `apply` dans gcodeLayer.ts) → pièce convertie affichée au même endroit.
- **Subdivision adaptative** : le firmware interpole linéairement en (R, C, Z, B), ce qui transforme une
  droite en spirale. Chaque segment est découpé (doublement de n jusqu'à 2048) tant que l'écart entre le
  point cartésien réel et l'interpolation polaire au milieu de chaque sous-segment dépasse `--tol`
  (0,01 mm). E réparti au prorata de la longueur ; F conservé (vitesse buse/plateau, comme le modèle de
  temps de la prévisualisation).
- **Angle dynamique** (mode `dynamic`) :
  - couches délimitées par `;LAYER_CHANGE`, `; <layer>` (IceSL), `;LAYER:` (Cura), sinon par montée de Z ;
  - par couche, carte de hauteur des points d'extrusion sur grille XY de 1 mm (moyenne z par cellule,
    lissage 2 mm) → normale `n = normalize(−∂z/∂x, −∂z/∂y, 1)` ;
  - la tête ne s'incline que dans le plan radial (C fixé par la position du point) :
    `B = atan2(n·r̂, n_z)`, borné à ±45° ; puis lissé le long du trajet (variation max ~2°/mm) ;
    trajets à vide : B interpolé vers celui du prochain dépôt ;
  - pivot calculé par l'inverse exact de `nozzleTip` : `R = r + 46·sin B`, `Z = z − 46·(1 − cos B)`
    (erreur si R < 0 → B réduit jusqu'à R ≥ 0).
  - mode `polar` : B = 0 partout (R = r, Z = z).
- Progression : `PROGRESS <0–100>` sur stderr ; erreurs : code de sortie ≠ 0 + message.

## 2. Electron : exécution Python + enregistrement
- `electron/preload.cjs` (nouveau, `contextBridge`) expose `window.apexDesktop` :
  `convertGCode({ text, mode, centerX, centerY })`, `onConvertProgress(cb)`, `saveGCode({ name, text })`.
- `electron/main.cjs` : `webPreferences.preload`, `ipcMain.handle('apex:convert-gcode')` → valide les
  arguments (mode enum, nombres finis), écrit l'entrée dans `os.tmpdir()`, `spawn` **sans shell** de
  l'interpréteur (embarqué `process.resourcesPath/python/python.exe` ; en dev : `python/` du dépôt avec
  `py -3` puis `python` du PATH), relaie la progression (`webContents.send`), renvoie le texte converti,
  nettoie les fichiers temporaires. `ipcMain.handle('apex:save-gcode')` → `dialog.showSaveDialog` +
  `fs.writeFile`.
- Embarquement : `scripts/fetch-python-embed.cjs` télécharge `python-3.12.x-embed-amd64.zip`
  (python.org) dans `build/python-embed/` (déjà gitignoré) ; `package.json` → `electron:build` /
  `electron:build:dir` l'appellent avant `electron-builder` ; `build.extraResources` :
  `build/python-embed → python`, `python → python-scripts` (hors asar, lisibles par python.exe).
- `src/types/apex-desktop.d.ts` : typage de `window.apexDesktop` (optionnel : absent dans `pnpm dev`
  navigateur → carte Conversion affiche « Disponible dans l'application Apex » ; Export retombe sur un
  téléchargement Blob).

## 3. Front
- `src/components/gcodeLayer.ts` : `ParsedGCode.nonPlanar` (part des mouvements d'extrusion avec
  |ΔZ| > 1e-4 au-delà de 5 %) et `bedCenter` retenu (exposé pour la conversion).
- `src/hooks/use-gcode-preview.ts` : garde le texte du fichier chargé (`sourceText`) et le texte
  courant ; `convert(mode)` → `apexDesktop.convertGCode` (état `conversion: { status, progress, mode,
  error }`) → charge le résultat via la même voie que `loadFile` (nom `<fichier>_apex.gcode`) tout en
  conservant la source 3 axes pour reconvertir dans l'autre mode ; `exportGCode()` → `saveGCode`.
- `src/components/GCodeConversionCard.tsx` + `.module.scss` (nouveau) : verre identique aux panneaux de
  Prévisualisation, largeur 440 px, sous le panneau du bas (zone bleue). Contenu : icône
  `TriangleAlert` + « G-code 3 axes (cartésien) : l'Apex imprime en coordonnées polaires. Convertissez-le
  avant l'export. » ; contrôle segmenté **Polaire / Angle dynamique** (présélectionné + mention
  « recommandé » si `nonPlanar`) ; bouton **Convertir** cyan ; pendant la conversion, barre de
  progression ; après : « Converti — polaire à angle dynamique » + possibilité de reconvertir.
  Montée via un nouvel emplacement de `CategoriesSidebar` (`previewBelowContent`, classe
  `.previewPanelBelow`, top = bas du panneau du bas + 16 px), même fondu `leavingToModeling`/`.morphing`
  que les deux panneaux. Vérifier le placement avec la barre d'aide (`TopRightMenu`, `PREVIEW_WIDTH`) et
  `PREVIEW_BOTTOM_MARGIN` (`src/utils/spaceMorphGeometry.ts`).
- `src/components/SliceSidebar.tsx` : prop `previewExport?: { enabled, onExport, reason }` passée par
  `src/pages/Index.tsx` quand `isPreviewActive` → bouton **EXPORT** (icône `Download`), activé si le
  G-code affiché est polaire (converti ou natif Apex), tooltip sinon « Convertissez d'abord le G-code
  3 axes ». Hors Prévisualisation : comportement Slice inchangé.
- `src/components/GCodeInfoPanel.tsx` : ligne Format « 4 axes (polaire Apex, converti — angle
  dynamique) » pour un fichier converti.

## Vérification
1. Script seul (Python 3 local) sur `research/gcode-samples/*.gcode`, modes `polar` et `dynamic`, puis
   re-parse des sorties avec le harnais esbuild déjà utilisé (`parseGCode` bundlé) :
   - `kind = polar`, filament total identique à la source (11,03 g Anycubic, 11,16 g Creality, 7,51 g IceSL) ;
   - écart max entre pointe de buse reconstruite (échantillonnée comme `createSampler`) et trajectoire
     cartésienne d'origine ≤ 0,02 mm ;
   - mode polar : B ≡ 0 ; IceSL dynamique : B ≠ 0 sur les pentes, |B| ≤ 45°, R ≥ 0 partout ;
   - types de ligne et générateur toujours détectés.
2. `pnpm exec tsc --noEmit -p tsconfig.app.json`, `pnpm lint`, `pnpm build`.
3. `pnpm electron:dev` : charger CreaPrint puis IceSL → carte visible, conversion avec progression,
   aperçu polaire (plateau tourne, tête s'incline sur IceSL), sélecteur → 4 AXES, EXPORT → boîte
   d'enregistrement, fichier rechargeable.
4. `pnpm electron:build:dir` : `release/win-unpacked/resources/python/python.exe` et
   `resources/python-scripts/gcode_to_polar.py` présents ; conversion fonctionnelle dans l'app empaquetée.
